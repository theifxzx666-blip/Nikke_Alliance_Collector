## 3. 名单采集（`alliance_ocr.py`）

- **昵称库只辅助、不判据**：页面 `(n/m)` 才是硬事实；库名只用于归位误读（`roster_fix`），不用来补人。
- **同一行合并**：`same_row` + `script_ok`（标点位豁免）+ `vote_spelling` 逐位投票；
  平票靠确定性规则（非标点优先）打破，不靠置信度。
- **跨屏**：`judge_roll` 判重叠，重叠不足就**往回小步补采**，不硬拼。
- **拖动**：`drag_at`，每步 3px / 28ms（≈107px/s）；到终点**原地停 0.20s 再松手**
  （一停就松手会被当成甩动，滑掉一整屏）。
- **标定**：昵称列预设随包带；换设备分辨率变了要重标一次。

## 4. 困难模式伤害采集（`hard_client.py`）

### 流程

```
接窗口 → 框选（识别与拖动都锁在框内）→ 采集本屏（人工确认）
  → 开始滚采：拉回顶部 → 逐屏 拖动/等停稳/识别/拼接 → 到底判定 → 导出 CSV
```

### 识别链路（一切以**伤害数字**为锚点）

1. 全屏 det 只用来找"伤害数字"这一列（实测 6/6，置信度 1.00）。
2. 成员名：伤害框左侧窄带，单行抠图重认；det 漏检时按几何带补认（本屏已识别成员名的最小 x）。
3. BOSS 名：成员框正下方横带，抠图重认 3 个左偏移投票（图标会被吃进名字）。
4. 等级：困难模式恒为蓝色 `LEVEL 1`，无信息量，不采。
5. 剩余血量：`pct_roi` 单独重认；>100% 按 /10 还原，还原后仍离谱就留空（不硬凑）。
6. 置信度：成员 / BOSS / 伤害三者**最低分**（短板决定这条能不能信），不用平均分。

### 拼接与到底

| 函数 | 作用 | 要点 |
|---|---|---|
| `splice` | 跨屏追加 | 位移只给候选，**定案靠全 k 内容扫描**；`k0<1` 不再短路成"没动" |
| `same_record` | 判同一行 | 成员/BOSS 相似 **且** 伤害相等（两边都读到才算） |
| `_all_known` | 判到底 | 这一屏的记录是否全在已采列表；**读到伤害就必须按伤害认** |
| `_fill_bottom` | 末尾回填 | 用**最后一屏**的读数补齐缺字段，**不往回滚**（方向反了） |
| `boss_norm` | BOSS 归一 | 掐前 1~2 字 / 尾巴全等 / 首字唯一 / 相似度 ≥0.6，全不中就原样留 |

### 参数（实测，别凭感觉改）

| 参数 | 值 | 说明 |
|---|---|---|
| 拖动速度 | 3px / 28ms ≈ 107px/s | 每屏稳定 2~3 行。**不要做运行时自校准**（见 §6.2） |
| 起手点 | 框内 45%（上拖）/ 55%（下拖） | 边缘 1/8 会拖到日期 tab 或空白上 |
| 每屏拖动距离 | `pitch × 2.5`，上限 `DRAG_MAX=420` | |
| 等停稳 | 300ms 后轮询 90ms，连续 2 帧稳定，最长 2.2s | |

## 6. 踩过的坑（按代价排序）

### 6.1 量位移：两个独立缺陷（最贵的一次）
`measure_vshift` 把每行压成笔迹强度标量做相关：
- **区域**：整屏测会被静止的标题栏/面板稀释，最优位移永远落 0。实测框内移动 240px：
  整屏 0px（相关 0.63）/ 框内 240px（相关 0.94）。→ 一律走 `_measure()` 裁框内。
- **方向**：旧函数只搜 `s>=0`，向上滚（内容下移）永远取不到 → 与"没动"同形。
  → `measure_vshift_signed()`，判据用 `abs(shift)`。

### 6.2 别做"运行时拖动参数自校准"
试探把"大步 286px/s"判成最优（188px），但那 188px 是**松手后惯性途中**的读数；
实际每次滚多少不可控，紧接着就 `重叠 2/5 对不上` → 收工 12 条。
**结论：速度固定 3px/28ms，不试探。**

### 6.3 "0 位移"有歧义
`0` 同时代表"没动"和"量不到"，而两者后续处理完全相反。任何位移判据都必须能区分
（现在靠：裁框内 + 带方向 + 内容对照）。

### 6.4 列表到底 vs 拼不上
到底时拖动会**回弹一格**，重叠核对会 0/5 全失败，但内容一条不缺。
`_all_known` 就是干这个的。缺了它会把"到底"误报成"可能缺行"，并跳过末尾回填。

### 6.5 框下沿截断
某条记录被采到时正压在框的下沿，BOSS 行落在框外 → 字段空。
再滚一屏它落到画面中部就完整了，所以**用最后一屏回填**。往回滚是反的（内容下移，只会更靠下）。

### 6.6 伤害不能单独当身份，(成员,BOSS) 也不能
- 同档同 BOSS 血量固定 + 普通难度一击必杀 → **不同人伤害完全相同**；
- 每人 3 刀，**带特化刀时同一 BOSS 会重复出现** → (成员,BOSS) 不唯一。
两个条件各挡一半错，必须同时用。

### 6.7 文字类
- **下划线**：OCR 把 `_` 读成空格（`NIKKE_01` → `NIKKE 01`），带下划线的昵称会多一人，需人工核。
- **末尾汉字被读成字母**：`铁匠` → `铁E`，相似度只有 0.5，靠"首字唯一"归一。
- **小数点丢失**：`79.5%` → `795%`，靠"剩余血量不超过 100%"兜。

### 6.8 工程类
- **bat 必须 GBK 编码、无 BOM**，否则中文路径 `cd` 变乱码。
- **测试不许写脏真实数据**：`e2etest` 曾漏重定向 `ROSTER`，把假名写进昵称库（83→85 轮）。
- **别拿全流程测试当回归**：会弹窗、抢光标。按 §7 分层。

### 2026-11-07 20:40 v1.23 补丁：Win10 浅色主题白屏

用户 Win10 实测截图：设置抽屉整片白、浅灰字看不见；开发机 Win11 深色主题复现不出来。

- **根因**：`QScrollArea` 的 viewport 是 Qt 内部控件，`autoFillBackground=True`，
  填系统 palette 的 `Base` 色。开发机是 `#2d2d2d`（深色主题），Win10 是 `#ffffff`。
  整套配色是 `rgba(255,255,255,N)` 叠深色底的半透明层 → 白底上就是白板。
- **修法**：① `QApplication.setPalette(T.dark_palette())`，在建任何控件之前，
  颜色与 QSS 同源；② `viewport().setAutoFillBackground(False)` + QSS
  `QScrollArea > QWidget > QWidget { background: transparent; }`。
- ⚠ **验收陷阱**：`QPalette()` 默认构造跟随本机系统主题，深色机器上测不出来。
  必须显式造 `Base=#ffffff / Window=#f0f0f0` 的浅色调色板再建 Shell。
  修复前抽屉中部像素 `#f0f0f0`，修复后 `#1b1e23`（数据来自 `w.grab().toImage()` 取点）。
- 教训：**任何依赖系统主题的默认值都是隐患**。深色 UI 必须在 QApplication 上钉死
  palette，不能指望 QSS 覆盖全部 —— QSS 按选择器匹配，Qt 内部控件（viewport、
  弹窗列表、菜单、提示气泡）没有 id 可写。

  ① `ROSTER_MIN_LEN=3` 让两字名连比对都不做；② `same_row` 要求**等长**，
  `UCOLVED`(7) / `HGOLIVER`(8) 直接 False；③ 阈值 0.62，真实值只有 0.50 / 0.53。
- 用真实库核对：`UCOLVED` → 最像 `HGOLIVER` 0.53、`蕭白` → 最像 `萧白` 0.50，
  用户两个判断都成立。
- 修：新增 `05-工具/zh.py`（~120 字常见繁简映射），`roster_cand` 在长度判断**之前**
  加繁简归一 —— 繁简不是"模糊"，归一后完全相同和字面命中同级，两字名也能走。
- **没放开两字名模糊归档**：`大白`/`萧白` 也是 0.5，但那是两个真人。防误伤优先。
- 复核的「成员不在库」加"最像谁（相似度）"，阈值 0.5 —— 再低就是瞎猜
  （三字名「老王」会撞 40% 的「大魔王」）。
- ⚠ 分工原则：**确定性差异自动修（繁简），不确定的只建议**。"显示不全 + 错位"
  这类光靠字符串救不了，交回给人判断。

### 2026-11-07 22:15 v1.30：补全要落回引擎自己的行

真机日志里同时出现两句互相打脸的话：`⚠ 第 [57] 条缺字段` 和
`复核：90 条 · 没发现互相对不上的地方`。

- **根因**：`emit_rows` 原来 `self.rowsChanged.emit(self._finalize([dict(r) for r in rows]))`
  —— 补全（BOSS 归一 + 同成员回填）都改在**副本**上。于是引擎的 `rows` 缺字段、
  界面的副本完整，同一份数据两个说法。导出用的是界面那份所以不报，但用户先看到的是告警。
- **修**：`_fill_known(rows)` 原地补全（引擎也跟着变准），`_apply_score(rows, hows)`
  只降副本的 conf。降分**不回灌**引擎 —— `patch` 判定拿 `nc > oc + 0.05` 比新旧读数，
  被降过分的数据比出来不公平。
- ⚠ 教训：**只要"处理后的数据"和"引擎手里的数据"是两份，收工自检就一定会说错话**。
  校验必须看最终数据，而不是中间态。

## 项目全史（v1.0 → v1.25）

> 逐版的修法细节在上面的日期小节里；这里只留**脉络与结论**，用于一次读完就知道
> 这个项目为什么长成现在这样。

### 阶段一：Tk 原型的判据积累（v1.0 之前，2026-10-27 ~ 11-07）

三个独立 Tk 界面（名单 / 普通伤害 / 困难伤害）共享一套底层：截图 → OCR → 拖动 → 拼接。
这一阶段产出的是**判据**，不是界面：

- **页面识别靠文本指纹，不靠像素坐标**。记录页/突袭主页没有联盟页签，概览页与成员页有 ——
  这条硬事实后来救了两次误判。
- **拖动用固定参数**（3px/28ms），位移靠相邻帧互相关测量，不靠计时估算。
- **跨屏拼接按行重叠对齐**，重叠不足就补回被跳过的行；整表按「伤害 + 成员名」去重。
- **名单归位有六道闸**（连续命中、跨轮缺失、别名、两字名不模糊归档等），
  防止 OCR 一次抖动就把两个真人合并。

### 阶段二：正式客户端 M1–M5（v1.0，同日）

目标是把困难伤害采集做成**唯一入口**的正式客户端：PySide6、竖版、HARD 优先、
F 区快捷键、实时跟随、强制 16:9。

结论：**判据不动，只换宿主**。所有采集逻辑留在 `05-工具/`，客户端只做窗口与交互。

### 阶段三：真机驱动的十一轮修复（v1.1 → v1.9）

这一段全部由真机日志驱动，每一次都是"日志里三行字 → 一处根因"：

| 版本 | 真机现象 | 根因 |
|---|---|---|
| v1.1 | 名单页误走 HARD；边框不能拉伸；序号超 9 不显示 | 页签没参与流程判定；无边框窗口没做命中测试 |
| v1.2 | 站突袭主页被当"认不出"，反复要求回主页 | `which_page` 没有突袭主页指纹 |
| v1.3 | 多盟无法分库 | 单文件昵称库 |
| v1.4 | 名单页在大厅没动作；窗口高度被锁死 | 桥只抓一屏；`plan_beside` 把高度压回游戏高 |
| v1.5 | 库管理藏在设置里太繁琐 | 高频操作不该放二级入口 |
| v1.6 | 重采没有覆盖提示；新建库后旧成员还在 | 缺状态刷新 |
| v1.7 | 名单数据串到伤害页；"记录不滚动" | 两页共用同一 `_rows` 与 model |
| v1.8 | 连接状态一栏三个"未连接" | 两处各自拼文案 |
| v1.9 | 建议尺寸缩完还是并排不下；Esc 停不下来 | 尺寸没算客户端宽度；Esc 是窗口内快捷键 |

**贯穿结论**：
1. **一个状态只能有一个绘制入口**（连接态、主按钮、底部信息行）。两处拼文案必然漂移。
2. **"某个按钮点了没反应"多半是异常被 Qt 信号栈吞了**（`btn_suggest` 未映射即此例）。
3. **写入型判断必须先查清依赖再动手**（撤旧工具前发现内置预设没打包）。

### 阶段六：发布前收尾与真机回归（v1.23 → v1.25）

v1.22 交付后用户连着报了一串问题，全部由真机截图 / 日志驱动，每一轮都挖出
"开发机上根本复现不了"的结构性缺陷：

| 版本 | 用户看到的 | 真正的根因 |
|---|---|---|
| v1.23 | 想发出去但产物是 200+ 文件 | 只有 onedir |
| v1.23 | 出问题没法查 | 打包后 `stdout` 为 `None`，日志一片空白 |
| v1.23 | Win10 设置页整片白 | `QScrollArea` viewport 吃系统调色板（浅色 = 白） |
| v1.23 | 明明 16:9 却报"没有采集区域" | 内置预设从 v1.0 起就没被读过 |
| v1.24 | 按 Esc 停不住，页面还在动 | 导航期不监听 + 取消后自动开滚采 |
| v1.24 | 快捷键在别的程序里也触发 | `RegisterHotKey` 独占，没做作用域 |
| v1.25 | 启动时在文件夹里释放文件 | 数据目录挂在 exe 旁边 |

**贯穿结论**：

1. **只在干净机器上才暴露的问题，开发机永远测不到。** 预设回退、首启播种、
   浅色主题，三个都是被"本机有历史状态"掩盖的。验收里"全新目录 + 临时 APPDATA"
   这一条必须真跑，不能靠源码态推断。
2. **Windows 的独占 API 不能靠回调过滤。** `RegisterHotKey` 注册期间按键压根
   不给别的程序，想"只在某些窗口生效"只能动态注册/注销。
3. **能复现才有资格说修好了。** 白屏用显式浅色 palette 复现、Esc 用状态竞争
   复现，两次都是先看到"坏的样子"再动代码。
